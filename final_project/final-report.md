# 面向四足机器人危险源识别的 RF-DETR 与受约束 SmolVLM 探索性研究

作者：孙驰（学号：2024311281）

指导教师：曾国坤
单位：哈尔滨工业大学（深圳）

## 摘要

四足机器人在未知环境中搜索危险源时，需要区分红色球形危险物与红方块、绿球等相似干扰物，并输出稳定、可追溯的离散决策。本文以五个历史仿真场景为基础，研究固定生产检测器 RF-DETR-Seg Medium 与轻量视觉语言模型 SmolVLM-256M 的互补性。数据审计发现 500 张图像中存在跨场景重复风险，因而全局隔离 99 张图像，保留 401 张图像和 444 个候选用于探索性评测。固定 RF-DETR checkpoint 在 401 张图像上全部推理成功，三目标类 Macro-F1 为 0.9635，危险目标 Precision、Recall 和 F1 分别为 0.9734、0.9892 和 0.9812。该 checkpoint 的训练样本谱系不可得，无法排除训练与评测重叠，因此结果只代表重复控制后的域内探索性表现。SmolVLM 自由生成基线的 444 个输出均违反严格单标签契约；冻结候选并采用续写 token 平均对数概率判别后，模型在 251 个锁定 oracle crop 上达到 100% 输出覆盖、0.7217 Macro-F1 和 100% 危险召回，但 23 个背景样本全部误判为红方块。最后，在 development 集上对 24 个低置信度真实 RF proposal 执行冻结级联，SmolVLM 的 24 个判断全部重复检测器类别，Macro-F1、危险召回和误报数均无改善，同时每次调用增加 5.11 s CPU P50 延迟。预注册的净增益门槛失败，级联按协议停止，最终推荐 RF-DETR-only。

关键词：四足机器人；目标检测；RF-DETR；视觉语言模型；SmolVLM；危险源识别

## 1 引言

### 1.1 研究背景与问题

四足机器人在室内未知环境中执行搜索任务时，需要从连续 RGB 图像中识别危险目标，并把视觉结果交给后续定位与任务状态机。该任务不仅要求类别判断正确，还要求低漏检、固定接口和可复查的决策过程。红色危险球与红方块、绿球等干扰物在颜色、尺度和遮挡条件上可能相近，单帧检测容易受到小目标、运动模糊、边缘截断和重复框影响。

检测 Transformer 将目标检测建模为集合预测问题，以对象查询和二分图匹配替代大量手工设计组件 [1]。RF-DETR 在该路线基础上面向实时检测与实例分割优化 [2]，适合作为机器人视觉链的候选生成器。SmolVLM 则面向低资源推理设计紧凑的多模态模型 [3]。从系统设计看，检测器负责定位和目标存在性，VLM 可能在相似类别之间提供语义复核；但这种互补关系必须通过真实 proposal 和冻结门槛验证，不能由模型类型直接推断。

### 1.2 研究问题与贡献

本文回答三个问题。第一，固定生产 RF-DETR checkpoint 在现有历史仿真语料上的检测表现和主要错误机制是什么。第二，固定候选评分能否修复自由生成式 VLM 的输出契约失败。第三，在低置信度真实 detector proposal 上调用 VLM 是否能产生可测量的净收益。

本文的工作包括三点：

1. 建立了按场景 seed 组织、带全局重复隔离和哈希证据的探索性评测协议，明确区分在线推理输入与仅用于离线评估的标签。
2. 将 SmolVLM 从自由文本生成改为四个冻结候选的 teacher-forced 评分，分别评估格式服从、对象语义分类和背景拒识能力。
3. 在冻结路由、融合和停止门槛后执行真实 RF proposal 级联。零增益结果被完整保留，并据此停止锁定级联与多视角扩展，形成 RF-DETR-only 的系统选择。

## 2 相关工作与课程知识

### 2.1 检测 Transformer

Transformer 的自注意力机制能够建模长距离关系 [4]。DETR 将其用于端到端目标检测，通过固定对象查询并行输出预测集合，并用集合级匹配约束重复预测 [1]。RF-DETR 进一步面向准确率与延迟权衡设计检测 Transformer，并提供目标检测和实例分割模型 [2]。本文不重新训练检测器，而是固定机器人项目中的 RF-DETR-Seg Medium checkpoint，把它视为生产候选生成器并审计其实际输出。

### 2.2 轻量视觉语言模型

SmolVLM 系列关注较小参数规模和较低推理资源需求，256M 模型能够接收图像与文本并生成语言输出 [3]。然而，机器人决策接口需要固定类别，普通生成式提示可能返回解释句、标点或同义表达。本文把“视觉判断能力”和“输出契约服从”分开测量，并采用固定候选续写概率将开放生成转化为封闭分类。

### 2.3 与课程内容的联系

本研究结合了课程中的视觉智能、语言智能和多模态智能。RF-DETR 对应视觉检测与实例分割；SmolVLM 以 Transformer 语言解码器连接视觉表征；受约束候选评分把生成模型的 token 概率用于判别任务；级联路由则把两个模块组合为可测试的决策系统。实验结果同时说明，多模态模块的加入不会自动带来系统收益，真实 proposal、背景拒识和时延必须共同进入验收条件。

## 3 方法

### 3.1 任务定义与类别

评测对象包含三个有框目标类：危险红球、干扰红方块和干扰绿球。缺少标签文件的历史帧在候选级 VLM 实验中按既有约定记为背景或未知，但不视为经过人工审计的严格负样本。RF-DETR 的主要指标为三目标类 Macro-F1；危险类另报告 Precision、Recall、F1、对象级 FP/FN 和图像级存在性 Recall。

检测框评估采用 box IoU 0.5，同类别预测按置信度降序与真值一对一匹配。Precision 为正确预测占全部该类预测的比例，Recall 为正确预测占全部该类真值的比例，F1 为 Precision 与 Recall 的调和平均，Macro-F1 为三个目标类 F1 的算术平均。数据没有真值 mask，因此不报告 mask IoU。

### 3.2 数据重复控制

原始资产包含五个仿真 seed、500 张 RGB 图像、426 个标注框和 117 个缺标签文件帧。审计检测到 15 个精确重复组以及跨 seed 的 dHash 近重复候选。协议保守隔离所有精确重复组成员和参与跨 seed 近重复候选对的图像，共隔离 99 张，保留 401 张图像与 444 个候选。五折按完整 seed 旋转，不随机拆分连续帧。

该协议只控制当前评测语料内部的重复风险。RF-DETR checkpoint 缺少训练样本清单、训练 seed、拆分与哈希，因此不能证明评测图像未参与训练。所有检测器结果均限定为固定 checkpoint 的域内探索性证据。

### 3.3 RF-DETR 基线

检测器使用 RF-DETR-Seg Medium，checkpoint SHA-256 为 `ec2de357f402901cf624835f11d5c54bb0eab8980d1268d7ee8a9122a446fa50`，置信度阈值固定为 0.5。401 个推理任务仅含图像路径和推理配置，不含标签、仿真真值或世界文件。推理结束后，离线评估器才连接封存标签并计算指标。

### 3.4 SmolVLM 基线与受约束评分

B1 使用 SmolVLM-256M-Instruct 自由生成，要求模型只输出四个 snake_case 标签之一。解析器只接受完整单标签，不从解释句中抽取关键词，也不在观察结果后增加同义词。

B2-A 继续使用自然类别词做 development 格式诊断。主要方案 B2-B 不生成自由文本，而是对四个冻结候选续写计算 teacher-forced token 平均对数概率并取最高分。候选文本、tokenization、EOS 处理、并列顺序和标签映射均在运行前冻结。B2 的对象输入来自真值框外扩 15% 的 oracle crop，背景输入为全帧，因此该实验只测候选区域中的语义分类，不是可部署的端到端检测。

### 3.5 真实 proposal 级联与安全融合

级联只在 seed 101/202 的 development 分区执行。路由器选择 RF-DETR 置信度位于 `[0.5, 0.7)` 的目标 proposal，并将预测框外扩 15% 后裁剪给 B2。任务生成和推理均不读取 ground truth 或 oracle box。路由队列包含 24 个 proposal，来自 22 张图像，占 development 中 172 个目标 proposal 的 13.95%。

安全融合规则优先保护危险类：推理错误或无结果时回退 RF；RF 的危险判断不得被降级；非危险 proposal 只有在 B2 判断为红方块或绿球时才允许互相重标；B2 对非危险 proposal 给出的危险判断不直接升级。继续条件同时要求危险 Recall 不下降、三目标 Macro-F1 严格提高、目标 FP 不增加、调用率不超过 15%。任一条件失败即停止锁定 seed 的级联推理。

## 4 实验设置

### 4.1 数据分区

| 用途 | Seed | 图像或候选规模 | 说明 |
|---|---|---:|---|
| RF-DETR 五折评测 | 101/202/303/404/505 | 401 张图像 | 每折一个完整 seed 作测试，汇总所有折外预测 |
| B2 development | 101/202 | 193 个候选 | 用于冻结门槛和级联可行性 |
| B2 锁定探索性评测 | 303/404/505 | 251 个候选 | B2-B 仅执行一次；B1 已观察这些 seed，非确认性测试 |
| 真实 proposal 级联 | 101/202 | 24 个 proposal | development-only；真实 RF bbox，无 GT/oracle 推理输入 |

### 4.2 运行环境

RF-DETR 在 Windows 11 CPU 环境运行，Python 3.13.12、PyTorch 2.12.0+cpu、Torchvision 0.27.0+cpu、rfdetr 1.9.4。SmolVLM 运行使用 PyTorch 2.15.0+cpu、Transformers 4.57.6、float32。所有报告时延均为该 CPU 环境实测，不能外推到 RTX 3080 Ti、RTX 3090 或机器人端。

### 4.3 可复现与证据约束

协议、队列、checkpoint、代码、原始 JSONL 与汇总指标均保存 SHA-256。RF-DETR 运行和停止后的级联运行分别由独立验证器复算，并将封存结果字节绑定到 Git evidence commit。完整确定性核查命令共通过 57 项测试。原四足机器人仓库和课程实验仓库均保持只读，所有新增代码与报告资产仅位于独立项目目录。

## 5 实验结果

### 5.1 RF-DETR 固定 checkpoint

RF-DETR 完成 401/401 张图像推理，未出现运行错误。表 2 给出主要结果。

| 指标 | 结果 |
|---|---:|
| 三目标类 Macro-F1 | 0.9635 |
| 危险目标 Precision / Recall / F1 | 0.9734 / 0.9892 / 0.9812 |
| 红方块 F1 | 0.9619 |
| 绿球 F1 | 0.9474 |
| 危险图像存在性 Recall | 0.9944 |
| CPU P50 / P95 延迟 | 653.1 / 743.3 ms |

![RF-DETR 固定 checkpoint 的三类指标](figures/rfdetr_pilot_metrics.png)

危险类共有 183 TP、5 FP 和 2 FN。两个对象级 FN 中，一个图像仍检出另一危险球，另一个图像没有任何 proposal，说明剩余漏检至少部分发生在候选生成阶段。若 detector 没有产生候选，proposal-conditioned VLM 无法恢复该对象。多项 FP 来自同一真值附近的重复框或边缘与背景预测。

### 5.2 自由生成与固定候选评分

B1 的 444 个输出均为连贯解释文本，却没有一个满足严格单标签契约，因此覆盖率、准确率、Macro-F1 和危险 Recall 均为 0。B2-A 恢复 100% 格式覆盖，但出现类别坍缩，development Macro-F1 为 0.2433。B2-B 在 193 个 development 候选上获得 0.6240 Macro-F1、0.9886 危险 Recall，并通过预注册的锁定运行门槛。

B2-B 随后在 251 个锁定 oracle crop 上执行一次，输出覆盖率为 1.0、准确率为 0.9084、Macro-F1 为 0.7217、危险 Recall 为 1.0。它正确分类 97 个红球、90 个红方块和 41 个绿球，但 23 个背景全部被判为红方块，背景 Recall 为 0。固定候选评分解决了输出格式问题，却没有获得可靠的目标存在性判断。

### 5.3 真实 proposal 级联

24 个真实 RF proposal 的 B2 推理全部成功，其中包括 6 个危险球和 18 个绿球。B2 对所有 proposal 都重复 RF 类别，安全融合和直接采用 B2 top-1 的诊断规则均未改变任何预测。

| 指标 | RF-DETR only | RF-DETR + B2 安全融合 |
|---|---:|---:|
| 三目标类 Macro-F1 | 0.96918 | 0.96918 |
| 危险 Recall | 0.98864 | 0.98864 |
| 目标 FP | 11 | 11 |
| B2 调用率 | 0 | 13.95% |
| B2 CPU P50 / P95 | 0 | 5114.7 / 5539.6 ms |

![真实 proposal 级联在 development 上没有改变指标](figures/cascade_development_comparison.png)

“Macro-F1 必须严格提高”条件为假，因此全部继续门槛没有通过。协议据此停止级联，没有在 seed 303/404/505 上运行级联推理，多视角实验继续暂缓且当前不执行。最终系统推荐 RF-DETR-only。该结果只否定当前冻结路由、模型和融合规则的净收益，不证明所有 VLM 级联都无效。

## 6 可复现实现与离线演示

项目采用旁路研究结构，不修改机器人生产代码。`configs` 保存冻结协议与外部路径，`data` 保存清单、标注引用与 seed 级拆分，`scripts` 提供运行和评估入口，`experiments` 保存原始结果与封存清单，`figures` 由汇总 JSON 生成。标签、仿真真值和 world/layout 文件只在离线评估阶段使用，不进入任何推理任务。

完整核查命令如下：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_checks.ps1
```

核查包括数据清单与分区契约、B1/B2 协议、RF-DETR 运行封存、级联队列重建、原始结果复算、Git evidence seal 和一致替换攻击回归测试。当前结果为 57/57 通过。离线报告图由封存指标生成，能够回放“检测器输出—VLM 路由—融合判断—停止决策”的完整证据链。本文未把离线回放包装为已完成的在线 ROS/Gazebo 演示。

## 7 讨论

### 7.1 结果解释

实验显示，VLM 的首要问题不是输出是否“看起来合理”，而是是否满足机器人接口。自由生成的解释文本在语义上连贯，却全部无法被严格解析。固定候选评分将生成任务转为封闭判别，立即恢复 100% 覆盖，说明输出契约与视觉语义能力需要分别评估。

B2-B 对三种对象类别的区分能力明显好于其背景拒识能力。oracle crop 已经向模型提供了目标位置，模型只需在有限区域内判断语义；当输入是背景全帧时，固定候选中又没有真正的“无目标”生成机制，模型倾向选择最接近的对象类别。因而 B2-B 可以作为 proposal 的语义分类诊断，但不能替代检测器。

真实级联没有修复错误，原因与数据分布有关。RF-DETR 在 development 上已具有较高 Macro-F1，路由区间中的 24 个 proposal 又全部被 B2 复述。与此同时，检测器的部分漏检是“无 proposal”，这种错误无法由 proposal-conditioned 复核器恢复。加入约 5.11 s 的 CPU 调用延迟后，零指标增益不足以支持继续实验。

### 7.2 有效性威胁

1. RF-DETR checkpoint 的训练数据谱系缺失，不能排除与 401 张评测图像重叠。
2. 数据只有五个历史仿真 seed，所有结果均为探索性证据。
3. 全局隔离 99 张图像只控制当前语料内部的重复风险，不能证明训练—评测隔离。
4. 缺标签帧沿用历史背景约定，可能包含未标目标。
5. B2 候选级锁定实验使用 oracle crop，非部署输入；B1 又已观察全部 seed，因此两者比较不是确认性测试。
6. 真实级联只在 seed 101/202 的 development 分区运行，没有锁定 seed 对照。
7. CPU 延迟不能代表 GPU 或机器人端时延。

### 7.3 课程学习反思

本项目最重要的实践认识是，模型指标、接口契约和系统安全边界必须一起设计。多模态模型并非只要接入检测器就能提高性能；若候选生成失败、背景拒识不足或调用延迟过高，语义能力无法转化为系统收益。冻结协议、保留负结果和设置停止门槛，避免了为获得“正结果”而反复调整阈值，也使最终选择能够由证据复查。

### 7.4 后续工作

若继续研究，首要条件不是租用更强 GPU，而是获得可审计的新数据。可以新增未参与开发的仿真或真实场景，并记录采集 seed、房间、视角、目标实例和完整标签。检测器应使用公开训练清单或在可审计拆分上重新训练。VLM 方向可研究显式“无目标”候选、全图与 proposal 联合输入，或对“检测器是否错误”进行监督学习；任何新方案都应重新冻结协议，并在新场景上评测。多视角融合只有在单帧级联产生可验证净收益后才值得启动。

## 8 结论

本文在不修改机器人生产代码的前提下，完成了 RF-DETR、SmolVLM 候选评分和真实 proposal 级联的探索性评测。固定 RF-DETR checkpoint 在重复控制后的 401 张历史仿真图像上取得 0.9635 三目标类 Macro-F1 和 0.9892 危险 Recall，但训练谱系缺失使其不能被解释为严格留出泛化结果。SmolVLM 的固定候选评分修复了自由生成的格式失败，并能在 oracle crop 中区分三种对象；其背景 Recall 为 0，说明它不具备独立的目标存在性判断。更关键的是，development-only 真实 proposal 级联对 24 个候选没有改变任何类别或指标，却增加约 5.11 s CPU P50 延迟。冻结净增益门槛因此失败，锁定级联与多视角没有继续执行。当前证据支持 RF-DETR-only 作为该项目的最终系统方案，同时把 VLM 结果保留为模型能力边界和负结果分析。
